## 0. 结论先行

- **推荐风格：B「Q 版扁平卡通（贴近新概念动画）」，HD 矢量/手绘质感 + 粗描边，不走严格像素风。** 原因：已有 144 课动画是扁平卡通，课文角色（NPC、剧情立绘）可直接沿用该风格，家长审核时“美术与课本动画统一”最容易过关；小学生对圆润 Q 版接受度最高。
- **现实约束**：这个方向的现成商用素材最少（免费素材 90% 是像素风），必须靠「素材包 + AI 辅助生成 + 少量定制」组合。若预算/工期紧，**方案 A（16-bit 像素风）是最快落地、成本最低的路线**，素材现成可买。
- **垂直切片（第一阶段）最小美术集合预算**：约 **¥1,500–3,500（$200–500）**，详见 B、C 节。
- 打击特效是用户最不满的点，**特效优先级最高**：有 CC0 的 PVFX Foundry（96x96、20FPS）可零成本起步。

## 1. 风格方向调研

### 1.1 DNF 本身的美术
DNF 是 2D 横版，开发商当年明确选 2D 是因为 3D「无法还原角色原画的味道」，且追求效率（Wikipedia【已打开】https://en.wikipedia.org/wiki/Dungeon_Fighter_Online）。其特点：手绘质感角色 + 高饱和技能特效 + 夸张打击感（顿帧、屏震、命中火花）。**学习点是“打击感的表现手法”，不是“像素还原”**——复刻其角色精度对我们不现实，但特效与节奏可借鉴。

### 1.2 三个候选方向

| | A. 16-bit 像素风 | B. Q 版扁平卡通（推荐） | C. DNF 式手绘像素 |
|---|---|---|---|
| 说明 | 角色 32–64px 高，低分辨率放大，硬边 | 角色 ~150–200px 高（1280x720 画面），粗描边、色块、少渐变，与新概念动画同款 | 角色 ~150–250px，手绘后降色、带 3D 渲染转像素的细腻帧 |
| 参考 | 免费包示例：https://opengameart.org/content/monsters-slime-skeleton-and-goblin 【已打开】（16x16，idle/run/attack/jump/hurt/death，CC-BY 4.0）；https://opengameart.org/content/elf-2d-game-sprite 【已打开】（chibi 像素，OGA-BY 3.0） | 本项目 `.cache/video/L001_sheet.jpg`（课文动画：蓝色扁平背景、圆脸厚轮廓人物）；Kenney UI Pack 的扁平按钮风格 https://kenney.nl/assets/ui-pack 【已打开】 | DNF 本体（见上 Wikipedia） |
| 对小学生吸引力 | 中高：“复古/Minecraft 感”男生喜欢；女生与低年级一般 | **高**：与每天看的新概念动画同一视觉语言，亲切；家长认可“不吓人、不暴力” | 高，但偏“网游/成人化”，家长审核风险略高 |
| 制作成本 | **最低**：素材包现成多、体积小（16x16 一帧才几百字节）；风格一致性容易靠“统一调色板重着色”保证 | **中高**：现成商用包少；需 AI 辅助或外包，骨骼动画（Spine/DragonBones 或 Phaser 补间）可省帧数 | **最高**：逐帧手绘，外包单角色 ¥3,000+ |
| 与新概念动画搭配 | 割裂（课文动画是平滑矢量，游戏是像素） | **一致**：NPC 立绘可直接从动画抠/仿绘 | 割裂 |
| 体积 | 极小（整套 <3MB） | 中（用骨骼动画或 8–12 帧/动作，整套 8–15MB） | 大 |
| 风险 | 家长觉得“粗糙/像劣质游戏”（用户已经吐槽“粗糙”，像素风若做不精易再被吐槽） | 素材来源与一致性（见 C 节） | 工期与成本 |

### 1.3 推荐：B（Q 版扁平卡通），并留 A 作为降级方案
- 推荐理由：①和课文动画统一；②小学生友好；③“粗糙”的主要来源不是像素与否，而是**无动画、无特效、无统一风格**，B 风格靠统一描边与色板即可显得精致；④程序特效（粒子、补间、屏震）在扁平风下观感很好，能降低美术成本。
- **降级路径**：若 B 的角色素材采购/AI 一致性做不出来，改用 A（购买一个统一画风的像素角色包 + 怪物包），UI/特效/背景部分两方案可共用，不浪费。
- **决策点**见 D 节第 1 项。

### 1.4 美术风格说明（一页，选 B 后执行）

**总体气质**：明亮、圆润、有趣、略带冒险感；“童话书里的地下城”，不血腥、不阴暗。

**比例**
- 画布 1280x720，角色站立高度：主角 ~170px，小怪 80–140px，精英 ~200px，Boss 300–420px。
- 角色 2–2.5 头身（Q 版），大头大眼，手脚短，便于小尺寸下辨识。
- 视角：纯侧视 + 轻微“地面透视”（地面条带可站立深度 ~180px，DNF 式）。

**描边**
- 外轮廓 4px 深色描边（#2B2A4A 深靛，不用纯黑），内部线条 2px；所有角色/怪物/道具/图标统一。
- 命中、受击时描边可瞬间变白（程序 tint）。

**色板（主色 + 功能色）**
- 主背景/天空：#7FD0FF、#A6E3FF（新概念动画蓝）
- 草地/安全：#6FD36B、#3FA94A
- 暖色强调（奖励/金币/暴击）：#FFC94A、#FF9F43
- 危险/怪物：#E8505B、#8B5CF6（幽灵/魔法）
- 深色阴影：#2B2A4A（统一，不用纯黑）
- 每张地图 1 个主色调 + 1 个点缀色，色相区分便于“按地图记忆”：草原绿、森林深绿、墓地紫、沙漠黄、冰原青、魔王城红橙。
- 对比度：文字与底色对比 ≥ 4.5:1；正确/错误不能只靠红绿区分（加图标 ✓/✗）。

**光影**
- 以色块明暗两层（亮部 + 阴影）为主，不用复杂渐变；角色脚下统一椭圆软阴影（alpha 0.3）。
- 背景使用“空气透视”：远景降饱和、偏冷，近景高饱和；
- 特效允许发光（additive blend），是画面里最亮最饱和的元素，引导视线。

**UI 风格**
- 圆角面板（半径 12–16px）、粗边框、轻微投影；按钮为“糖果感”色块，按下 2px 位移。
- 字体：标题用圆润手写体，正文用无衣线（见 C.4）；英文课文单词用大字号（≥28px）。
- 图标 64x64，同一描边规则，稀有度用底色框区分（白/蓝/紫/橙/红）。
- 剧情对话框：底部通栏，左右立绘，名牌 + 打字机效果。

## 2. 网页游戏资源规格（调研与建议）

依据：
- 贴图最大尺寸：iPhone 6S 一代的 GPU 上限即 4096x4096，“所有地方都支持 4096”；但**更保险是单张图集 ≤2048x2048**，4096 在老移动设备上上传 GPU 时可能卡顿；非 2 的幂纹理在部分 GL 实现上会被放大浪费显存（html5gamedevs 讨论串，搜索摘要）：https://www.html5gamedevs.com/topic/27923-maximum-image-dimensions-on-mobile/ 【搜索摘要】
- 图集的意义：同图集的精灵可合批为一个 draw call（Phaser 教程，搜索摘要）：https://phaser.io/tutorials/advanced-rendering-tutorial/part2 【搜索摘要】
- 工具：TexturePacker（付费，有免费版）或开源 free-tex-packer / ourcade vscode-texture-packer：https://github.com/ourcade/vscode-texture-packer 【搜索摘要】

**本项目建议规格（Windows 桌面浏览器为主，平板兼顾）**

| 项目 | 规格 |
|---|---|
| 画布 | 1280x720，Phaser 缩放 FIT |
| 角色帧 | 256x256 单帧画布（角色实际 ~170px 高，留出武器挥动空间）；Q 版 HD 路线 |
| 动作与帧数 | idle 6 帧 @8fps；run 8 帧 @12fps；attack 6–8 帧 @15fps；skill 8–12 帧 @15fps；hurt 3 帧；death 6 帧；victory 6 帧（结算用） |
| 怪物帧 | 小怪 128x128：idle 4、move 6、attack 6、hurt 2、death 6；精英 256；Boss 512x512，复杂 Boss 可用补间+分件骨骼 |
| 图集 | 单张 ≤2048x2048，PNG（或 WebP，Chromium 支持；Windows 主流浏览器均支持），JSON atlas；一个职业一张图，一个地图的怪物一张图，按地图**懒加载** |
| 特效 | 96x96 或 128x128 帧，12–20fps（PVFX Foundry 为 96x96/20fps）；用 additive 混合，同图集 |
| 背景 | 视差 3–4 层，每层 1920x720 可横向平铺（远景可 960x720 拉伸）；JPG/WebP 压缩 |
| 图标 | 64x64，一张 1024x1024 图集 |
| 立绘 | 512x768（半身），WebP，每人 3–4 表情（共用身体可只换脸部叠加层） |
| 体积预算 | **首屏（Boot+城镇）≤ 5MB 压缩后**；单张地图资源 ≤ 3MB（进入副本时懒加载并显示进度）；全游戏资源 ≤ 40MB；音频另计（BGM 用 OGG/MP3 64–96kbps）。纯本地/内网自用时限制可放宽，但保持预算有利于将来对外发布 |
| 压缩 | PNG 用 pngquant（256 色，体积减 60–70%）；整包 gzip/brotli；字体子集化（见 C.4） |

### 4.3 AI 生成美术（补充方案）
适用：Q 版怪物概念图、背景、立绘、章节插画；**不适合直接用于逐帧动画**（帧间不一致）。

**如何保证角色一致性**
1. 先画**角色设定表**（正面/侧面/表情，固定色板与服饰）并人工修正，之后所有生成以其为参考图（image-to-image / 参考图 / LoRA / 风格参考）。
2. 固定：同一模型+同一种子风格 prompt 模板、统一描边描述、统一背景（纯色/透明）。
3. 动画：用“拼件骨骼”——AI 出单帧立绘，人工切成头/身/手臂/腿/武器图层，用 Spine/DragonBones 或 Phaser 补间做 idle/run/attack，**一致性问题转化为一张图的问题**。适合 B 方向，成本比逐帧低很多。
4. 背景：AI 出整图后手动切层，补全遮挡区域。
5. 批量后统一调色（调色板映射）+ 统一加描边（程序/PS 脚本）。

**授权/法律风险**（Wayline 文章【已打开】https://www.wayline.io/blog/ai-art-generation-game-dev-legal-licensing ；SpriteCook 博客【搜索摘要】https://www.spritecook.ai/blog/is-ai-art-ok-in-indie-games）
- 纯 AI 生成作品在美国通常不受版权保护（缺少人类作者），意味着**无法阻止别人复制**；人工大量修改的部分才可能受保护。
- 训练数据版权争议，输出若与现有作品近似可能被指控侵权。
- 各平台条款不同（有的平台主张权利、有的授予完整商用权）。
- 建议：保留提示词与修改记录；选条款明确授予商用的工具；**中国大陆发布需遵守《生成式人工智能服务管理暂行办法》及相关标识规定**（本条未查证原文，若将来对外发布需法务/平台规则确认）；家长自用阶段风险低。
- 如果将来上架 Steam，需按其规则披露 AI 内容（SpriteCook 摘要，【搜索摘要】）。
